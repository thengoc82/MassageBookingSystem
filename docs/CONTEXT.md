# Domain Glossary

## Agent usage

This file is the single canonical domain source of truth. Read it first when starting any feature or clarifying terminology. `docs/adr/` holds Architectural Decision Records — check before proposing architectural changes. Update this file when introducing new domain concepts. Write a new ADR for significant architectural decisions.

## Core Entities

**Customer**
A person who books massage services, identified by phone number. Created automatically on first booking. Can be blocked via the NG List.

**Therapist**
Staff member who performs massage services. Assigned to exactly one Shop. Works according to Shifts. Can be requested by name for single-person Bookings only.

**Shop**
A branch location offering massage services. Has opening hours, Courses, Therapists, and receives Bookings.

**Course**
A massage service offered at a Shop. Two types: `main` (primary service) or `addon` (supplementary service). Has duration and price.

**Booking**
A confirmed service reservation. Contains 1+ people, each assigned exactly one main Course plus zero or more addon Courses. Has a unique booking code generated by the system.

**Shift** (full name: Therapist Shift)
A recurring weekly time block when a Therapist is scheduled to work (e.g., "Monday 08:00-17:00"). A Therapist can have multiple Shifts across the week.

**Customer Restriction** (also called "NG List")
A block preventing a Customer from making new Bookings. Placed by Admin with a reason. Can be active or inactive.

## Lifecycle States

**Booking Status**
- `Booked` — confirmed, customer has not yet arrived
- `CheckedIn` — customer arrived, service in progress
- `CheckedOut` — service completed (terminal state)
- `Cancelled` — customer or admin cancelled (terminal state)

Valid transitions:
- `Booked` → `CheckedIn` → `CheckedOut`
- `Booked` → `Cancelled`

Only `Booked` status allows modification.

## Roles

**Admin**
System operator who manages Shops, Courses, Therapists, Shifts, and Bookings. Can check customers in/out. Can manage the NG List.

**Customer** (public role)
Person using the booking system. No authentication required — identified by phone number.

## Booking Flow (Optimistic Availability)

1. Customer browses shops, selects date/guests/duration/course/add-ons
2. System returns available slots (capacity = active therapists on shift − overlapping bookings).
   With `show_therapists=true` it also returns the therapist list + per-slot `availableTherapistIds`.
3. Customer picks a time slot (optionally a specific therapist, e.g. via the dashboard Gantt)
4. AI agent or UI collects remaining info (phone, therapist preference)
5. Customer confirms
6. System immediately calls `POST /api/bookings` — **no reservation hold**
7. If successful: booking code returned
8. If slot is gone (therapist taken by another booking during the flow):
   - System refreshes availability
   - Suggests nearest available slots
   - Customer chooses again

Availability is **optimistic** — shown as it was at query time. The actual check happens at booking creation under a row-level lock.

## Business Rules

### Customer
- Customer is identified by phone number. If new, auto-create on booking.
- Blocked customers (NG List) cannot create bookings.

### Therapist Assignment
- **1-person booking:** Can request a therapist via `therapistPreferenceType` + `therapistPreferenceValue`
  (`specific` + therapist id, `gender` + `Male`/`Female`, or `no_preference`). System locks that
  therapist at confirm time for `specific`.
- **Group (2+):** Cannot assign a specific therapist. System auto-assigns by least-loaded first.
- Therapist must belong to the same Shop as the Booking.
- Therapist must be on an active Shift covering the Booking time.
- Therapist must have no overlapping Booking.

### Service Assignment
Each person in a Booking receives exactly 1 main Course + 0 to N addon Courses.

### Booking Modification
- Only `Booked` status bookings can be modified.
- Changing time triggers therapist availability re-check at the POS level.

### General Constraints
- Booking code is unique system-wide, format `BK{YYYYMMDD}{4digits}`.
- Course type must match: `main` for primary services, `addon` for add-ons.
- Shop must be open at the selected time.
- Each person in a booking gets exactly 1 main course + 0..N add-ons.

## Terms NOT in Use

- "Appointment" — we say Booking
- "Service Provider" — we say Therapist
- "Package" — we say Course (can be main or addon type)
- "Branch" — we say Shop
- "Time Slot" — no longer a stored entity, availability is calculated dynamically from therapist shifts and bookings
- "Wait list" — not supported
- "Reservation" — removed. No time-limited holds. See ADR 0002.
- "Membership tier" — we track member_rank (Silver/Gold/Platinum) but it's not used in booking logic yet
